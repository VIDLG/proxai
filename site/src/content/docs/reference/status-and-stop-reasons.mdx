# Status and Stop Reasons

Different protocols use different names for “the model stopped producing output”. ProxAI treats these as related protocol concepts, not interchangeable raw fields.

<ProxaiCallout type="note" title="One response does not mean one stop reason shape">
  Non-streaming Anthropic Messages returns one final `message` object whose stop-related fields follow the official required/nullable contract. Measured provider omissions are repaired, when supported, by provider normalization before strict wire deserialization.
</ProxaiCallout>

## Presence and nullability

Wire structs mirror official field contracts rather than accepting missing and null interchangeably:

  columns={['Case', 'Representation or handling']}

    ['Known provider omits a required-nullable field', 'A narrow provider normalization may insert explicit null before protocol deserialization when a measured fixture documents the deviation.'],

  ]}

A successful final Anthropic `message` therefore follows the official requiredness of stop fields. Failed or interrupted upstream responses are handled as errors rather than by weakening the protocol carrier or inventing a stop reason.

## Contract

- ProxAI observes streaming terminal events; it does not treat arbitrary byte-stream closure as semantic completion.
- ProxAI does not fabricate provider-specific reason details such as upstream `code`, `param`, or matched stop sequences.
- Cross-protocol mappings should preserve behavior first, exact field spelling second.
- A model refusal is semantic output, not an upstream/request failure; do not map it to Responses `failed`.
- Responses `failed` is a response lifecycle/error state and should not be fabricated as Anthropic `refusal` without refusal content.
- Tool-call terminal states must remain distinct from natural text completion.
